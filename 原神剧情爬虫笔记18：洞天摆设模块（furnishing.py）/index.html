原神剧情爬虫笔记18：洞天摆设模块（furnishing.py）

发表于2026-08-31|更新于2026-08-31|开发记录
|总字数:1.8k|阅读时长:6分钟|浏览量:

本文档记录了《原神》观测枢洞天（摆设/家具）爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。

一、模块概述

模块名称：furnishing.py
功能：从米哈游观测枢 Wiki 爬取所有洞天摆设/家具的详细信息，包括：

  • 摆设名称、区域（室内/室外）、类型（墙饰/摆件/地貌/套装等）
  • 品质（二星/三星/四星/五星）
  • 摆设获取方式、图纸获取方式
  • 物品描述（核心文本，包含背景/文化叙述）
  • 获取途径（制作/宝箱/活动等）
  • 相关套装（所属好感套装名称）

输出：每个摆设保存为一个 .txt 文本文件，存放在 data/cleaned/furnishing/ 目录下。

增量策略：

  • 使用 crawled.json 记录已爬取的摆设 ID。
  • 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
  • 若官方更新了内容，需手动从 crawled.json 中删除对应 ID，重新运行以更新。

十、注意事项

  1. 文件名清洗：摆设名称可能包含特殊字符（如 「」、·、制表符、空格等），safe_filename 会去除首尾空白并替换所有空白字符为下划线。
  2. 无描述则跳过：若摆设没有物品描述（good_desc.rich_text 为空），视为无剧情价值，该摆设被跳过。
  3. 获取途径保留：good_desc.attr 中的获取途径作为补充信息保留。
  4. 套装可能为空：部分摆设没有相关套装，related_sets 字段保持空字符串。
  5. list: null 防御：rich_base_info 的 list 字段可能为 null，代码已增加防御性检查。
  6. 制作材料跳过：cave_base_info 中的制作材料为纯数值，已跳过。

列表结构 扁平列表 扁平列表 扁平列表

输出粒度 每个摆设一个文件 每个 NPC 一个文件 每个动物一个文件

十二、后续优化方向

  1. 制作材料提取：目前 cave_base_info 中的制作材料已跳过，未来可根据需要添加为补充信息。
  2. 套装关联展开：相关套装目前只是名称，未来可爬取套装详情，建立“摆设 → 套装”的关联索引。
  3. 支持分类过滤：通过命令行参数指定只爬取特定区域（室内/室外）或特定类型的摆设。
  4. 内容变更检测：通过哈希值检测内容变化，替代手动删除 ID。
