原神剧情爬虫笔记20：灰眸图鉴模块（gray_eye.py）

发表于2026-08-31|更新于2026-08-31|开发记录
|总字数:3.1k|阅读时长:10分钟|浏览量:

本文档记录《原神》观测枢「灰眸」图鉴模块的接入过程，包括频道发现、三类详情组件解析、增量抓取、文本输出和一次实际解析故障的修复过程。它既是模块说明，也是后续新增图鉴频道时可复用的排查案例。

一、模块背景与目标

2026 年 8 月，观测枢新增了独立的「灰眸」图鉴分类。该分类记录了与影域探索有关的系统说明、臻冰造物、机关、外观与可交互的讯息文本。

虽然它不完全等同于传统剧情任务，但其中的设定说明、人物背景和交互对话具有语料价值，因此将整个频道纳入爬虫，而不是只手动保存少量剧情词条。

模块名称：src/modules/gray_eye.py
模块标识：gray_eye
显示名称：灰眸
频道 ID：278
输出目录：data/cleaned/gray_eye/
输出粒度：一个观测枢词条对应一个文本文件，文件名为稳定的词条 ID，例如 509292.txt。

模块目标如下：

  1. 自动读取「灰眸」频道目录，发现新增词条。
  2. 提取图鉴说明、造物信息、外观获取方式和交互对话。
  3. 忽略纯图片与图标，保留可阅读、可检索的文字。
  4. 使用已有的增量记录机制，避免重复请求和重复写入。
  5. 接入统一运行入口、模块报告、manifest 与数据校验流程。

四、实际问题：interactive_dialogue 被漏抓

首次运行时，18 条「灰眸」词条成功保存，但 509292（「灰眸」讯息）被列为失败，原因是页面没有 dress_base_info、artifact_list_v2 或 multi_table，而是完全由 interactive_dialogue 组成。

该问题不能直接判定为“官方页面没有文本”。检查详情接口后可以发现，页面内容实际存在于对话树中：

此外，官方数据存在两种等价写法：

  1. 标准格式：对话树位于 data.list[] 的每一项内；
  2. 扁平格式：root_id、child_ids、contents 直接位于 data 顶层，list 为空或不存在。

因此 parse_interactive_dialogue() 的处理策略为：

  1. 优先读取 list；
  2. 若列表为空但顶层存在完整树字段，则构造一个临时列表项；
  3. 从 root_id 开始深度优先遍历 child_ids；
  4. 使用 visited 集合避免异常环路；
  5. 每个节点按“选项在前、台词在后”的顺序写入。

该写法会在所有 HTML 标签之间插入换行，连 span、链接等内联标签也会被拆开。对于结构化字段，可能出现：

新规则只将真实段落、列表和 <br> 视为换行；字段型内容通过 clean_inline_html() 压缩为单行。灰眸模块从一开始就使用这一规则：

  • 概述、造物名称、制造需求、表格单元格：单行清洗；
  • interactive_dialogue 的正文：保留必要的段落结构；
  • 模块之间：用标题与空行明确分隔。

这一区分很重要：如果把所有换行都合并，任务剧情、书籍段落和对话可读性会下降；如果保留所有标签断行，结构化字段又会变得破碎。

九、增量策略与重抓方法

增量状态记录在本地 config/crawled.json：

  • 已记录的 ID：直接跳过；
  • 新发现的 ID：请求详情、保存文本、写入增量记录；
  • 请求失败或没有成功保存的词条：不会写入成功记录，下次运行会自动重试。

如果官方修改了既有词条，或修复了解析代码，需要重抓特定条目时，应只删除 crawled.json 中相应的 gray_eye ID 后再运行模块。不要删除整个数据目录或全局爬取记录，以免无关模块被大规模重复请求。

十、验收结果与后续维护

2026-08-30 的首次接入与修复后：

  • 目录发现：19 条；
  • 成功保存：19 条；
  • 失败条目：0；
  • gray_eye 已进入统一 manifest；
  • 全项目数据校验通过。

后续维护时重点关注：

  1. 目录数量变化：游戏更新后先比较目录条目数，再运行增量抓取。
  2. 新组件 ID：若新词条显示“没有可保存的文本”，优先检查其详情 JSON 的 component_id，不要直接认定内容为空。
  3. 图片与文字的边界：纯图片继续忽略；图片附带的标题、获取方式、描述等文字应保留。
  4. 对话树分支：当前策略保留所有分支，最大化保存设定信息；如未来需要“单一路线”语料，应另外设计分支选择规则，不应覆盖原始完整文本。
  5. 语料质量检查：新增模块抓取后都应重建 manifest，并运行校验和重复文本检查。
