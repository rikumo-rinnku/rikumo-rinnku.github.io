原神剧情爬虫笔记04：角色逸闻模块（character_anecdote.py）

发表于2026-08-31|更新于2026-08-31|开发记录
|总字数:1.7k|阅读时长:5分钟|浏览量:

本文档记录了《原神》观测枢角色逸闻（游逸旅闻）爬虫模块的设计思路、技术实现、API 分析和使用方法，适用于项目维护和后续扩展。

一、模块概述

模块名称：character_anecdote.py
功能：从米哈游观测枢 Wiki 爬取所有角色的逸闻纪事（游逸旅闻），包括：

  • 逸闻纪事（主要剧情故事）
  • 剧情彩蛋（隐藏对话）
  • 角色洞天对话（尘歌壶互动）
  • 七圣召唤对局对话
  • 幻想真境剧诗对话
  • 生日邮件内容

输出：每个独立事件保存为一个 .txt 文本文件，存放在 data/cleaned/anecdote/ 目录下。

增量策略：

  • 每次运行重新请求所有角色详情页。
  • 通过检查文件是否已存在来决定是否保存（已存在则跳过）。
  • 若官方更新内容，需手动删除对应 .txt 文件，重新运行以更新。

组件 用途
Python 3.12+ 运行环境

logging 日志记录（文件 + 控制台）
项目内部模块 client, parser, config_loader

4.2 角色逸闻详情 API

  • URL: https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page
  • 参数: app_sn=ys_obc, entry_page_id={角色ID}, lang=zh-cn
  • 核心字段:
    • page.modules[]：所有内容模块（基本信息、逸闻、彩蛋等）。
    • page.template_layout.tab[]：定义页面布局和模块分组。
      • tab_name：标签页名称（如“逸闻纪事”、“剧情彩蛋”等）。
      • module_group[]：每个分组包含多个模块 ID，对应 modules 中的实际内容。

五、数据结构与解析逻辑

5.1 内容类型识别

通过 template_layout.tab 中的 tab_name 识别不同类型的内容：

tab_name 类型标识 文件名前缀 说明
逸闻纪事 逸闻纪事 （无） 主要逸闻故事
剧情彩蛋 剧情彩蛋 彩蛋_ 隐藏对话/事件
角色洞天 角色洞天 洞天_ 尘歌壶互动对话
七圣召唤 七圣召唤 七圣召唤_ 七圣召唤对局对话
幻想真境剧诗 幻想真境剧诗 剧诗_ 剧诗模式对话
生日邮件 生日邮件 生日邮件_ 角色生日邮件内容

5.2 模块解析规则

每个 module_group 包含多个模块 ID，通过 component_id 区分类型：

component_id 类型 提取内容
rich_base_info 元信息 标题（名称）、简介、关键词、备注
interactive_dialogue 对话树 完整对话（按顺序）

特殊处理：

  • 彩蛋的标题来自 关键词 字段，格式化为 彩蛋：关键词。
  • 若缺少元信息但有对话模块，则使用模块名或标签名作为标题。
  • 地图展示、角色展示等辅助模块被跳过。

5.3 对话树遍历 (parse_interactive_dialogue)

对话树结构包含：

  • root_id：根节点 ID。
  • child_ids：节点之间的连接关系（支持分支）。
  • contents：每个节点的内容（option 玩家选项，dialogue 角色台词）。

遍历策略：

  1. 从 root_id 开始深度优先遍历。
  2. 先输出 option（玩家选项），再输出 dialogue（角色台词）。
  3. 递归访问所有子节点，直到叶子节点。

六、输出格式与文件命名

6.1 文件命名规则

  • 角色名：从 title 中去掉 【逸闻】 后缀。
  • 前缀：根据内容类型添加（见 5.1）。
  • 标题：从元信息中提取的“名称”或“关键词”，或模块名/标签名。
  • 非法字符（\ / : * ? " < > |）替换为 _。

十、注意事项

  1. 增量更新限制：若官方更新了已保存的逸闻内容，需手动删除对应的 .txt 文件，重新运行才会更新。
  2. 请求频率：每次请求间隔 1~2 秒，避免触发反爬。若需加速，可适当缩短间隔。
  3. 网络超时：如遇 SSL 超时，可检查网络连接或增加 timeout 参数。
  4. 文件名长度：某些标题过长可能超出 Windows 路径长度限制（260 字符），但目前未见问题。
  5. 模块扩展：如需增加新类型的标签（如“角色邀约”），只需在 target_tabs 列表中添加即可。

十一、后续优化方向

  1. 支持命令行参数：通过 argparse 控制爬取范围和模式。
  2. 统计精确化：让 process_character 返回保存数量，更新 total_new_anecdotes。
  3. 内容变更检测：通过哈希值检测内容变化，替代手动删除文件。
  4. 多线程并发：使用 ThreadPoolExecutor 加速（需控制并发数）。
