原神剧情爬虫笔记14：NPC与商店模块（npc.py）

发表于2026-08-31|更新于2026-08-31|原神剧情爬虫笔记
|总字数:2.5k|阅读时长:8分钟|浏览量:

本文档记录了《原神》观测枢 NPC & 商店爬虫模块的设计思路、API 分析、数据结构解析、实现细节及踩坑记录，适用于项目维护和后续扩展。

一、模块概述

模块名称：npc.py
功能：从米哈游观测枢 Wiki 爬取所有 NPC 和商店的详细信息，包括：

  • NPC 名称、地区、类型（活动/商人/其他/任务）
  • 牌手挑战、对话奖励、特殊效果（心声/秘闻馆情报）
  • 基本信息（性别、位置、职业、功能、编者注等）
  • 相关任务列表
  • NPC 对话树（interactive_dialogue 模块）
  • 商品列表 / 锻造列表（collapse_panel 中的表格）

输出：每个 NPC 保存为一个 .txt 文本文件，存放在 data/cleaned/npc/ 目录下。

增量策略：

  • 使用 crawled.json 记录已爬取的 NPC ID。
  • 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
  • 若官方更新了内容，需手动从 crawled.json 中删除对应 ID，重新运行以更新。

3.2 NPC 详情 API

  • URL: https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page
  • 参数: app_sn=ys_obc, entry_page_id={NPC ID}, lang=zh-cn
  • 核心字段:
    • page.modules[]：所有内容模块。
    • modules[].components[].data：实际数据（JSON 字符串）。
    • 常见模块与组件：
      • npc_base_info：NPC 基本属性（性别、位置、职业、功能、编者注）。
      • collapse_panel / rich_base_info：富文本描述或表格（商品列表、锻造列表等）。
      • interactive_dialogue：NPC 对话树（玩家选项与 NPC 对话）。
      • multi_table：结构化表格数据（备用）。
      • map_desc：地图展示图片（无文本，忽略）。
      • card_group_info：七圣召唤挑战卡片（纯图片链接，忽略）。

4.3 表格解析（collapse_panel 中的 HTML 表格）

使用 BeautifulSoup 解析 HTML 表格，正确处理 rowspan 和 colspan 属性：

  1. 第一遍：提取所有行的单元格信息（文本、rowspan、colspan），计算最大列数。
  2. 第二遍：展开 rowspan/colspan，构建规整的二维数组。
  3. 动态扩展：当 colspan 导致索引超出当前行长度时，自动扩展列表，避免 IndexError。
  4. 异常捕获：如果表格解析失败，自动回退到 clean_html_to_text 简单清洗，保证程序不崩溃。

十、踩坑记录与注意事项

10.1 对话树 list 字段为 None

现象：爬取“海莉”时抛出 TypeError: 'NoneType' object is not iterable。

原因：部分 NPC（如“海莉”）的 interactive_dialogue 组件中，data.list 为 null，数据直接存放在顶层字段（root_id、contents）。

解决方案：在 parse_interactive_dialogue 中增加 fallback 逻辑：如果 list 为空或 None，但顶层存在 root_id 和 contents，则自动构造虚拟的 list 项。

10.2 表格解析 IndexError: list assignment index out of range

现象：爬取“阿创【「天目锻冶屋」学徒】”时抛出 IndexError。

原因：表格中存在复杂的 colspan 和 rowspan 合并，当前解析逻辑在计算列索引时出现越界。

解决方案：

  1. 动态扩展列数：当 col_idx + c 超出 expanded_row 长度时，自动扩展列表，避免索引越界。
  2. 异常捕获：在表格解析外层增加 try-except，若解析失败则回退到 clean_html_to_text 简单清洗，确保程序不崩溃。

10.3 其他注意事项

  1. 跳过同伴赠礼模块：module_name == "同伴赠礼" 的模块包含好感套装奖励表格，对剧情向 RAG 价值极低，直接跳过。
  2. 文件名清洗：NPC 名称可能包含特殊字符（如 【】、「」），使用 safe_filename 替换为下划线。
  3. 空内容过滤：若 NPC 详情页无任何可提取文本（如仅有图片），该 NPC 将被跳过，不生成文件。

十二、后续优化方向

  1. 对话树分支标记：当前对话树平铺所有节点，未来可加入缩进标记，区分不同对话分支。
  2. 商品表格结构化：将商品列表解析为 JSON 或 Markdown 表格，为 RAG 提供更精确的数据检索。
  3. 支持增量更新：通过内容哈希检测变更，避免手动删除 ID。
  4. 多线程并发：使用线程池加速爬取（需控制并发数避免风控）。
  5. 命令行参数：支持通过 argparse 指定 test_limit 或特定的 NPC ID 列表。

本文档记录了《原神》观测枢敌人爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。 一、模块概述 模块名称：enemy.py 功能：从米哈游观测枢 Wiki 爬取所有敌人的详细信息，包括： 敌人名称、类型（BOSS/精英/普通）、元素（火/水/雷/冰/岩/草/风/无）、攻击方式（近战/远程/混合） 简介（列表页 summary 字段） 背景故事（good_desc 模块，含折叠面板展开） 位置信息（timeline_base_info 模块，若存在） 输出：每个敌人保存为一个 .txt 文本文件，存放在 data/cleaned/enemy/ 目录下。 增量策略： 使用 crawled.json 记录已爬取的敌人 ID。 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。 若官方更新了内容，需手动从 crawled.json 中删除对应 ID，重新运行以更新。 二、技术栈 组件 用途 Python 3.12+ 运行环境 requests + tenacity HTTP 请求与自动重试 json 解析 ...
