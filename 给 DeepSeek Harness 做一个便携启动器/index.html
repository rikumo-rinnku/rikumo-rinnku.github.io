给 DeepSeek Harness 做一个 便携启动器

大家好，这里是璃雲。

之前分享 DSH 的使用方式后，有同学提到：自己没有学过计算机相关知识，看了文档，还是不知道该怎么把程序运行起来。于是，我把 DeepSeek Harness 和需要的运行环境整理到一起，做了一个 Windows 桌面启动器，希望把第一次使用的门槛降下来。

这篇文章记录它的制作思路、几处核心代码，以及打包时遇到的问题。

制作思路：把运行环境一起带走

整体结构很简单：用批处理脚本作为入口，Python 的 Tkinter / CustomTkinter 负责桌面界面，Node.js 负责运行 DeepSeek Harness，Python 子进程模块负责启动、停止和读取引擎输出。

完整发布包携带 Python、Node.js 和已经构建好的引擎依赖。用户解压后双击 start.bat，就能通过按钮启动服务，再进入 Web UI。使用在线模型仍需联网，并配置自己的 API 凭据。

启动器会从 3080 开始寻找可用端口，并将 DSH 用户目录、缓存和临时目录指向便携包内的位置。

另一个需要处理的细节是网页认证：端口能连接，不代表直接打开地址就能使用。 引擎启动日志会输出包含 ?token=... 的地址，启动器需要提取本次 token，在服务就绪后打开完整 URL。--no-open 则让浏览器的打开时机由启动器统一管理。

打包遇到的问题：循环依赖链接

最初直接用 7-Zip 压缩整个目录，工具显示有二三十万个文件，速度很慢，还出现了深层路径报错。

检查后发现，不跟随目录链接时，实际约有 8 万个文件，但目录里有数千个符号链接。其中存在这样的依赖关系：

因此，我没有直接删除 node_modules，而是把分发方式改为：真实文件只收集一次，目录链接记录到清单，启动时再恢复。

最终结果

这次构建收集了 78,984 个文件，将 6,085 个目录链接保存为清单，生成的发布包约 633 MiB。现有依赖完整保留，没有通过批量删除依赖来压缩体积。

打包流程还会将 ZIP 解压到独立目录，验证链接恢复、GUI 模块加载、CLI 启动和网页资源，再移动整个目录重复检查。这些检查已通过；真实模型请求和全部插件功能尚未覆盖。

后续更新时，准备好运行环境和已构建的引擎，运行 pack.bat 就能重新生成并验证发布包。源码仓库本身不包含这些运行环境，想直接体验的朋友请下载完整包。
