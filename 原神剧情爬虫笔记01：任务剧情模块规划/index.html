原神剧情爬虫笔记01：任务剧情模块规划

本文档记录了从零开始构建《原神》任务剧情爬虫的完整过程，包括 API 分析、数据结构解析、子任务拆分、对话树遍历、日志与报告机制等，适用于后续维护和扩展。

一、项目背景

在完成角色模块后，项目进入任务模块的开发。任务模块的目标是：

  1. 获取任务列表：从观测枢 API 获取所有任务的 ID、名称、类型、区域、版本号。
  2. 获取任务详情：对每个任务，请求详情 API，解析出子任务结构、流程梗概、详细对话。
  3. 子任务拆分：将包含多个子任务的任务拆分为独立文件，便于 RAG 检索。
  4. 增量爬取：记录已爬取的任务 ID，避免重复请求。
  5. 日志与报告：记录爬取过程中的状态，生成可追溯的爬取报告。

2.2 任务详情 API

  • URL: https://act-api-takumi-static.mihoyo.com/hoyowiki/genshin/wapi/entry_page
  • 参数: app_sn=ys_obc, entry_page_id={任务ID}, lang=zh-cn
  • 核心字段:
    • page.modules[]: 所有内容模块（基础信息、任务概述、任务过程、剧情对话等）
    • page.template_layout: 定义模块的布局和层级关系，用于识别子任务
    • page.ext.fe_ext: 任务分类信息（类型、区域、版本号）

观测枢的任务详情页面中，一个传说任务可能包含多个子任务（幕/章）。子任务通过 template_layout 中的 module_group 层级关系来组织。

3.2 识别规则

  • parent_group_id = 0：顶层组（包含主任务的基础模块）
  • parent_group_id ≠ 0：子任务组，其 parent_group_id 指向顶层组的 module_group_id

  • 子任务名称优先使用 module_group.name，若为空则从模块名称中推断

使用深度优先遍历，从 root_id 出发，按照 child_ids 依次访问所有节点。

关键点：

  • 先输出 option（玩家选项），再输出 dialogue（角色台词），确保对话顺序正确。
  • 遍历时记录已访问节点，避免循环（数据中一般不会出现循环，但作为安全措施保留）。
  • 由于数据是树状结构，我们无法区分"主线"和"分支"，因此遍历所有节点，保留完整的对话内容。

九、常见问题与解决方案

问题 原因 解决方法
对话顺序混乱 直接遍历 contents 字典，而非按树形结构顺序 使用深度优先遍历 child_ids
选项出现在对话之后 先提取 dialogue 后提取 option 调整顺序：先 option 后 dialogue
子任务名称无法识别 module_group.name 为空 从模块名称中推断（如“骑士之追缉”）
文件包含不需要的内容（地图说明、任务奖励） 未过滤排除模块 在 parse_subtasks 中过滤 EXCLUDED 列表
文件名包含非法字符 任务名中包含 / 等特殊字符 使用 re.sub(r'[\\/*?:"<>|]', '_', name) 清洗

十、后续扩展建议

  1. 对话树分支选择：当前遍历所有分支，如果希望只保留“主线”对话，可以设计策略（如始终选择第一个子节点）。
  2. 性能优化：全量爬取时，可以使用多线程并发请求（注意控制频率）。
  3. 数据校验：定期运行校验脚本，对比任务列表和实际文件数，确保完整性。
