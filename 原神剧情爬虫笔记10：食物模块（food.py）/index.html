原神剧情爬虫笔记10：食物模块（food.py）

发表于2026-08-31|更新于2026-08-31|开发记录
|总字数:2.6k|阅读时长:9分钟|浏览量:

本文档记录了《原神》观测枢食物爬虫模块的设计思路、API 分析、数据结构解析和实现细节，适用于项目维护和后续扩展。

一、模块概述

模块名称：food.py
功能：从米哈游观测枢 Wiki 爬取所有食物的详细信息，包括：

  • 食物名称、食物类型（回复类/复活类/体力类/攻击类/防御类/暴击类/生命上限/治疗加成/合成药剂/特殊食物）
  • 星级（一星至五星/其他）、获取方式（NPC购买/任务获取/宝箱获取/其他）
  • 是否产出特殊料理（是/否）
  • 各变体的描述、使用效果、获得方式、食谱获得、加工材料

输出：每个食物保存为一个 .txt 文本文件，存放在 data/cleaned/food/ 目录下。

增量策略：

  • 使用 crawled.json 记录已爬取的食物 ID。
  • 每次运行先检查 ID 是否已记录，若已记录则跳过，避免重复请求。
  • 若官方更新了内容，需手动从 crawled.json 中删除对应 ID，重新运行以更新。

六、核心函数说明

函数 职责
get_food_list() 获取所有食物的 ID、名称、简介和分类标签（类型/星级/获取方式/是否特殊料理）。

十、注意事项

  1. 变体识别：一个食物条目可能包含多个 material_base_info 模块，需全部提取。变体类型通过 name 字段判断（以"奇怪"开头、以"美味的"开头、包含"特殊"/“特色”/“专属”）。
  2. 加工材料换行问题：clean_html_to_text 会错误地将材料拆成多行，需使用 extract_materials_text 单独处理。
  3. 空内容过滤：只有至少有一个有效文本字段（描述/效果/获得方式/食谱/材料）的变体才会保留。
  4. 星级重复：详情页的 star 与列表页 ext 中的星级重复，已在列表提取，详情页的 star 字段不单独使用。
  5. 特殊料理判断（含已知缺陷）：特殊料理的识别依赖 name 中的关键词（“特殊”、“特色”、“专属”）。这是当前代码的真实判定规则，但存在已知分类缺陷：部分特殊料理的名称不含上述关键词（如「解闷泡泡糖」），会被漏判而归入普通版，待在代码侧修复。另外，并非所有有特殊料理标志的食物都一定有特殊料理变体。
  6. 图片链接舍弃：img 字段仅包含图片链接，无文本价值，已跳过。
  7. 空的 collapse_panel：部分食物详情页包含空的 collapse_panel 模块，已通过空值判断跳过。

核心组件 good_desc、collapse_panel material_base_info（多个变体）
核心内容 背景故事、技能描述、数值 描述、使用效果、加工材料
变体数量 固定 1 个 多个（奇怪/普通/美味/特殊料理）
特殊处理 引用替换、折叠面板展开 加工材料换行压缩
数据用途 RAG 语料库（剧情知识） RAG 语料库（食物 lore、效果描述）

十二、后续优化方向

  1. 支持命令行参数：通过 argparse 控制爬取范围和模式。
  2. 内容变更检测：通过哈希值检测内容变化，替代手动删除 ID。
  3. 多线程并发：使用 ThreadPoolExecutor 加速（需控制并发数）。
  4. 变体合并优化：如果多个变体的内容完全相同（仅名称不同），可考虑合并输出。
  5. 材料链接解析：当前仅提取加工材料的纯文本，未来可考虑提取材料 ID 建立关联。
