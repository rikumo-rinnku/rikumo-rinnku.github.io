原神剧情爬虫笔记03：核心模块实现详解

发表于2026-08-31|更新于2026-08-31|开发记录
|总字数:1.4k|阅读时长:5分钟|浏览量:

本文档记录了《原神》剧情爬虫项目中 src/core 目录下四个基础模块的设计思路、实现细节和关键代码。这些模块为上层爬虫提供了统一的请求、解析、存储和配置管理能力。

1. client.py —— 统一 HTTP 请求客户端

功能：封装 HTTP 请求，提供自动重试、超时控制、默认请求头等特性，避免在每个爬虫模块中重复编写请求逻辑。

设计思路：

  • 使用 requests 库发送同步请求。
  • 利用 tenacity 库实现重试机制（默认重试 3 次，指数退避等待）。
  • 设置合理的超时（30 秒）和默认 User-Agent，模拟浏览器行为。
  • 仅实现 get 方法（当前够用），预留 post 接口。

  • 上述代码未限定重试条件，因此所有抛出的异常都会触发重试（包括网络错误，以及 raise_for_status() 抛出的 4xx/5xx HTTPError）。若希望仅对网络错误重试，可通过 retry=retry_if_exception_type(ConnectionError) 等条件限定。
  • 可根据目标站点的反爬策略调整重试参数和头信息。

2. parser.py —— HTML 文本清洗工具

功能：将 HTML 格式的剧情内容转换为纯文本，去除标签、多余空白，保留段落结构。

设计思路：

  • 使用 BeautifulSoup 解析 HTML，lxml 作为解析器（速度快）。
  • 调用 get_text() 提取纯文本，用换行符分隔块级元素。
  • 使用正则表达式将连续的多个换行符压缩为至多两个，保持可读性。

注意事项：

  • 如果将来遇到非 HTML 的文本来源（如纯 JSON 字段），可以增加适配函数。
  • 清洗后的文本适合直接存入 .txt 文件供 RAG 使用。

3. storage.py —— 增量爬取状态与文件存储

功能：

  • 管理已爬取记录 (crawled.json)，支持按模块和条目 ID 检查、标记。
  • 提供统一的文本保存接口，按模块和条目名称组织目录结构。

设计思路：

  • 使用 JSON 文件存储已爬取的条目记录，现行标准结构为 { "module_name": { "ID": "名称" } }（按 ID 去重，值存条目名称）；代码同时兼容读取旧版 { "module_name": [id1, id2, ...] } 列表格式。
  • 每次检查时加载整个 JSON 到内存（条目数最多几千，性能可接受）。
  • 保存文本时自动创建 data/cleaned/{module}/{名称}.txt（非法字符替换为 _）。

注意事项：

  • crawled.json 文件初始内容应为 {}，若为空文件会导致 json.loads 失败，故做了空内容处理。
  • 使用条目名称作为文件名（与各模块的实际输出一致），非法字符替换为 _，避免文件系统问题。

4. config_loader.py —— 频道配置管理

功能：读取 config/channels.json 文件，提供按模块名获取频道 ID 的接口。

设计思路：

  • 将不同模块（角色、敌人、武器等）的频道 ID 集中配置在 JSON 文件中，便于维护和扩展。
  • 在爬虫模块中通过 get_channel_id("character") 获取，避免硬编码数字。

  • 未来扩展新模块只需在 JSON 中添加条目，无需修改代码逻辑。
  • 可在配置中加入 enabled 字段，配合调度器选择性运行模块。

📌 总结

src/core 模块为爬虫项目提供了以下基础能力：

模块 职责 关键依赖
client.py 可靠的 HTTP 请求 requests, tenacity
parser.py HTML → 纯文本转换 beautifulsoup4, lxml
storage.py 增量记录 + 文件保存 标准库 json, os
config_loader.py 读取频道配置 标准库 json, os

这些模块的设计遵循单一职责和可复用原则，使上层爬虫模块（如 character.py）只需关注业务逻辑（如何解析列表和详情），而无需关心网络重试、文件存储等底层细节。
